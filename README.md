# AsterGraph

기본 주소는 감귤 기획전의 준비, 관계 검수, 납품 변경 대응을 한 사례로 보여주는 60초 시연입니다. 이전 마트 시연은 `/?demo=retail-case`, 부산 물류센터 시연은 `/?demo=logistics`에서 실행합니다.

## 실행

Node.js 22.12 이상 권장. 이 작업은 Node.js 26.0.0 / npm 11.12.1에서 검증했습니다. Vite의 런타임 요건은 [공식 시작 문서](https://vite.dev/guide/)를 참고하세요. 설치 버전은 `package-lock.json`에 고정되어 있습니다.

```sh
npm ci
npm run dev -- --port 5173
```

브라우저에서 <http://127.0.0.1:5173>을 엽니다. 로컬 정적 파일만 제공하는 개발 서버입니다. 의존성 설치에는 네트워크가 필요하며, 설치 후 앱 실행에는 외부 네트워크가 필요하지 않습니다.

배포 빌드를 로컬에서 확인하려면:

```sh
npm run build
npm run preview -- --port 4173
```

## 감귤 기획전 · 졸업작품 시연

기본 화면에서 **60초 데모 시작**을 누르세요. 0초에 행사 준비, 15초에 관계 검수, 25초에 공급사 공지, 45초에 승인본 질의로 이어집니다. 녹화 모드에서는 한국어 자막을 표시합니다. R은 처음부터 재생, 숫자 1–4는 장면 바로가기, Esc는 녹화 모드 종료입니다.

**묶음으로 구축**을 누르면 카탈로그의 준비 자료 3개에서 공급사·상품·행사·매장 515개 개체와 관계 후보 871개를 구성합니다. 전체 대조 내역에서 ID나 문서명으로 검색하고 원본 행을 열 수 있습니다. 공급사 공지와 납품 변경 기록은 25초 이후 변경 관리에서 사용합니다.

관계 후보 870건은 원본과 일치합니다. 담당자는 예외 1건의 행사 ID를 행사 계획 2행과 대조하고 **제안 적용 · E-07 → 묶음 승인 · v1**을 누릅니다. 변경 관리에서는 새 공지의 영향 범위를 확인하고 **변경 승인 · v2**를 누릅니다. 승인한 근거, 범위와 담당 역할은 승인 이력에서 확인합니다. 수동 승인은 현재 브라우저에 보관하고 자동 재생은 격리된 상태에서 실행합니다. 입력 문서와 추출 후보는 고정된 시연 자료입니다.

새 발표 영상은 [1080p](artifacts/videos/batch-review/AsterGraph-Batch-1080p.mp4)와 [4K](artifacts/videos/batch-review/AsterGraph-Batch-4K.mp4)로 제공합니다. 프로덕션 미리보기(4173번 포트)를 실행하고 Chrome, ffmpeg, ffprobe가 설치된 환경에서 `node scripts/render-knowledge.mjs`로 다시 생성할 수 있습니다. 직전 [앱 소스](artifacts/backups/ontology-before-batch.zip), [1080p 영상](artifacts/videos/ontology-lifecycle/AsterGraph-Ontology-1080p.mp4), [4K 영상](artifacts/videos/ontology-lifecycle/AsterGraph-Ontology-4K.mp4)도 보관합니다.

## 이전 마트 시연 · /?demo=retail-case

**지식 운영 워크스페이스**에는 상품 386건, 납품 상태 386건, 행사 98건, 매장 배정 387건, 공지 1건을 담은 로컬 샘플이 있습니다. 데이터 카탈로그의 **레코드 탐색**에서 원본·상품명·ID로 검색하고 결과를 선택하면 실제 파일과 원본 위치를 확인할 수 있습니다. 상품 또는 상태 기록에서 **검토 이력 보기**를 열면 기준 등록일, 상태 변경일, 담당 팀과 검토 메모가 표시됩니다. 검토 시작·완료·재검토 기록은 상품 및 대상 수정본별로 현재 브라우저에 보관합니다.

- **직접 조작** — 공지에서 **납품 변경 확인**을 누르고 이전 기록을 대조합니다. **관련 행사 찾기**에서 추천 질문을 검색하고, **참여 매장 추적**을 눌러 행사와 매장의 관계를 확인합니다. **매장 배정표 대조**에서 원본 행을 확인한 뒤 **검토 메모 정리**를 누릅니다. 메모는 담당자가 검토 버튼을 누르면 저장됩니다.
- **자동 재생** — 공지(0초), 변경 확인(7초), 행사 찾기(15초), 매장 추적(25초), 배정표 대조(39초), 검토 인계(49초) 순서로 진행하고 60초에 멈춥니다. 숫자 1–6은 장면 이동, R은 처음부터 재생합니다.
- **발표 영상** — [1080p MP4](artifacts/videos/retail-case/AsterGraph-Retail-Case-1080p.mp4) · [4K MP4](artifacts/videos/retail-case/AsterGraph-Retail-Case-4K.mp4). 직전 [지식 운영 영상](artifacts/videos/knowledge-operations/AsterGraph-KnowledgeOps-1080p.mp4)과 [프론트 소스 백업](artifacts/backups/retail-before-case-story.zip)도 별도로 보관합니다.
- **녹화 모드** — **녹화 모드**를 누르고 R을 누르면 발표용 자막으로 재생합니다. Esc로 컨트롤을 복원합니다.
- **시연 범위** — 사전 구성한 문서 관계를 사용합니다. 변경 전후 비교, 연결 탐색, 영향 대상 집계와 지정 질문 조회는 브라우저에서 수행합니다. **시연 데이터** 배지에서 설명을 확인할 수 있습니다.
- **원본** — CSV 3개, XLSX 1개, PDF 1개가 앱에 포함되어 있습니다. 샘플 내용을 변경할 때는 `src/features/retail/dossier.json` 수정 후 `ARTIFACT_MODULES=/path/to/node_modules node scripts/generate-retail-sources.mjs`로 원본을 다시 생성합니다. 재생성 시에만 해당 경로의 `@oai/artifact-tool`과 로컬 Chrome이 필요합니다.

## 기존 물류 시연 · 수동 조작

이하의 조작법과 영상은 [기존 30초 시연](http://127.0.0.1:5173/?demo=logistics)에 해당합니다.


1. 기본 화면 Operations Intelligence에서 **추천 질문**을 누릅니다.
2. **영향 분석**을 누르면 0.6초 피드백 후 영향 38건, 대체 가능 26건, 우선 대응 12건이 표시됩니다.
3. **LM-1001**을 선택하면 SKU_A 서울 가용 26개 중 이 주문 1개를 배정할 수 있다는 근거가 보입니다.
4. **우선 대응 필요** KPI를 누르고 **LM-1027**을 선택하면 SKU_B 서울 재고 0개로 대체 불가인 이유가 보입니다.
5. **대응안 시뮬레이션**에서 위험 38건 → 잔여 12건과 대응 대상 그룹을 비교합니다.
6. **대상 보기**로 그룹별 주문을 확인하고 **계획 비교 보기**로 돌아옵니다. **시뮬레이션 해제**는 원래 분석 화면으로 복귀합니다.

KPI와 필터는 같은 계산 결과를 사용합니다. 목록은 페이지로 전체 주문에 접근합니다. 그래프 노드를 누르면 개념·출처·관계 설명이 표시됩니다. Overview의 **영향 분석하기**, Ontology Explorer의 개념 선택, Data Sources의 **관계 보기**도 동작합니다.

지원 질문은 다음 한 개이며 공백 정규화만 허용합니다. 다른 질문에는 지원 범위 안내를 보여주고 결과를 만들지 않습니다.

> 부산 물류센터가 48시간 중단되면 어떤 주문에 영향이 있나요?

질문을 수정하면 이전 결과와 계획은 해제됩니다. 분석 가정은 **가정 보기**에서 확인합니다.

## 30초 시연 및 녹화

하단 **30초 데모 시작**은 Overview부터 시작합니다. 일반 초기 진입 화면과 데모 첫 화면은 다릅니다.

| 시간 | 장면 |
|---|---|
| 0–4초 | 부산 센터 장애, 분산된 4개 시스템 |
| 4–7초 | Operations Intelligence와 관계 연결 |
| 7–12초 | 질문 입력, 11.4초 분석 실행, 0.6초 피드백 |
| 12–19초 | 38/26/12 결과, 14.2초 LM-1001 근거 선택 |
| 19–27초 | 대응안 시뮬레이션, 38→12 전후 비교 |
| 27–30초 | 브랜드와 결론, 30초에 종료 후 정지 |

**녹화 순서**

1. 앱을 실행한 뒤 브라우저 콘텐츠 뷰포트를 1920×1080 또는 1440×900, 확대율 100%로 맞춥니다. 브라우저 창의 외곽 크기와 콘텐츠 뷰포트는 다릅니다.
2. 폰트와 앱이 로드된 뒤 **리셋**을 누릅니다.
3. **녹화 모드**를 누릅니다. 재생 컨트롤이 숨겨지고 자막 영역으로 바뀝니다. Demo 배지는 유지됩니다.
4. 화면 녹화를 시작한 다음 **R** 또는 **Space**를 누릅니다. R은 항상 0초부터 재생합니다.
5. 30초에 자동 종료된 엔딩 프레임까지 녹화하고, 시작 전·종료 후 여분을 잘라 정확히 30초를 사용합니다. 브라우저 캡처 프레임률에 따른 한 프레임 오차는 영상 편집에서 맞춥니다.
6. **Esc**로 녹화 모드를 해제합니다.

전경 탭에서 재생하세요. 다른 탭으로 전환하여 페이지가 숨겨지면 자동 일시정지됩니다. 화면 녹화 파일이나 내레이션은 앱이 자동 생성하지 않습니다. 일반 모드는 컨트롤을 보여주며, 자막은 녹화 모드에서 표시됩니다.

| 조작 | 동작 |
|---|---|
| Space | 재생 / 일시정지. 일반 버튼에 초점이 있으면 해당 버튼의 표준 Space 동작을 우선합니다. |
| R | 0초부터 재시작. 녹화 모드 유지. |
| ← / → | 이전 / 다음 장면. 재생 여부 유지. |
| 1–6 | 해당 장면 시작으로 이동. |
| Esc | 열려 있는 대화상자 닫기 또는 녹화 모드 해제. |
| 리셋 버튼 | 질문·결과·필터·선택·계획·시계·녹화 모드를 초기화하고 기본 화면 복귀. |

입력창·IME 입력 중에는 전역 단축키가 동작하지 않습니다. 수동 조작은 자동 재생을 일시정지합니다. **재개**하면 해당 시각의 정해진 데모 상태로 복원합니다. 장면 이동도 이전 클릭 이력과 무관하게 상태를 재구성합니다. 시스템의 동작 줄이기 설정에서는 타이핑과 전환 애니메이션을 생략하고 같은 타임라인과 결과를 유지합니다.

## 생성된 라이트 모드 데모 영상

- [4K MP4 원본](artifacts/videos/AsterGraph-Light-4K.mp4): 3840×2160, 30fps, 30초.
- [Full HD MP4 공유용](artifacts/videos/AsterGraph-Light-1080p.mp4): 1920×1080, 30fps, 30초.
- 두 파일 모두 H.264이며 앱 자막이 포함된 무음 영상입니다. 마지막 3초는 온톨로지 관리 기반을 보여줍니다.

1920×1080 앱 레이아웃을 브라우저의 2배 픽셀 밀도로 직접 렌더링했습니다. `scripts/render-demo.mjs`는 실제 앱의 R 단축키와 자동 시연을 실행하고, 브라우저 시계와 CSS 애니메이션을 프레임 단위로 진행하여 900프레임을 캡처합니다. 화면 이미지 교체나 분석 결과 주입 없이 기존 UI를 기록합니다. 공유용 파일은 4K 원본에서 Lanczos 필터로 축소합니다.

재생성에는 로컬 Google Chrome과 `ffmpeg`가 필요합니다. 빌드 후 별도 터미널에서 preview 서버를 실행한 상태로 캡처합니다.

```sh
npm run build
npm run preview -- --port 4173 --strictPort
# 다른 터미널에서:
node scripts/render-demo.mjs
```

기본 출력 폴더는 `artifacts/videos/`이며 `DEMO_URL`, `DEMO_OUTPUT` 환경 변수로 서버와 출력 경로를 바꿀 수 있습니다. 캡처는 전용 브라우저 세션에서 실행하며 사용 중인 탭이나 테마 설정을 바꾸지 않습니다. `capture-report.json`에 주요 장면의 KPI·근거·테마·화면 크기 검증 결과를 저장합니다.

## 데이터와 한계

- 주문 120건(LM-1001~LM-1120), 상품 3개, 센터 2곳의 결정적 목업입니다.
- 부산 PENDING 38건 = SKU_A 26건 + SKU_B 12건. 나머지 82건은 직접 영향이 없습니다.
- 서울 가용 SKU_A 26개 / SKU_B 0개. 주문번호 오름차순으로 같은 SKU의 재고 한도 내에서만 계획 배정합니다.
- 주문당 상품 1개·수량 1·동일 납기 구간, 서울에서 배정 주문을 출고할 수 있다고 가정합니다.
- 운송 시간, 도로 상황, 비용, SLA, 예약 재고, 현실의 출고 우선순위는 계산하지 않습니다.
- 계획 배정은 원본 주문·재고와 분리됩니다. `38 → 12`는 조건부 시뮬레이션 결과이며 실제 지연 감소 실적이 아닙니다.
- Ontology v1.2 · Managed와 DEMO CONNECTED는 목업 상태입니다. 온톨로지 편집·변경 관리·실제 연동은 없습니다.
- 모바일·작은 창에서는 세로 스크롤로 모든 기능을 사용합니다. 무스크롤 녹화의 주 대상은 위 두 목표 해상도입니다.

## 검증 명령

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 로컬 **Google Chrome**을 사용합니다(`channel: chrome`). Chrome이 없는 환경에서는 먼저 설치하거나 Playwright 설정의 채널을 로컬 환경에 맞춰 변경하세요. 별도의 서버가 없으면 테스트가 Vite를 자동 실행합니다. 테스트에는 실제 30초 재생 3회가 포함되어 약 2분이 걸립니다.

- 단위 테스트: 집합·재고 한도·SKU·결정성·원본 불변·질문 지원·이벤트 경합·타임라인 복원.
- 브라우저 테스트: 전체 업무 흐름, 대표 주문 2개, 필터·페이지, 대화상자, 보조 화면, 기록 모드·정지·재개·리셋, 뷰포트, 외부 요청 차단.
- `test-results/`: 실행 결과 JSON, 핵심 프레임 스크린샷, 실패 시 trace. 테스트 산출물이므로 Git 제외 대상입니다.
- 상세 실측 결과와 검증 한계: [docs/VERIFICATION.md](docs/VERIFICATION.md).

- `src/styles/`: 디자인 토큰과 적응형 레이아웃.

## 로고와 화면 모드

헤더 오른쪽 **태양/달 버튼**으로 라이트·다크 모드를 전환합니다. 기본값은 다크이며 선택한 모드는 새로고침 후에도 유지됩니다. 분석 결과와 계획은 그대로 유지되고, 자동 재생 중 전환하면 재생이 일시정지됩니다. 녹화 전에 모드를 선택하세요. Record Mode에서는 전환 버튼이 숨겨집니다.

확정한 **AG Aperture(A안)** 로고와 윤곽선 워드마크를 사이드바, 모바일 헤더, 엔딩과 브라우저 탭에 적용했습니다. 투명 배경 SVG 원본은 `public/astergraph.svg`(어두운 바탕용), `public/astergraph-light.svg`(밝은 바탕용)입니다. [라이트 화면](docs/screenshots/light-plan-1440.png)과 [브랜드 엔딩](docs/screenshots/light-brand-1440.png)을 참고하세요.

최종 로고 원본은 `public/brand/`의 `horizontal-*`, `stacked-*`, `wordmark-*`, `symbol-*` SVG입니다. [사용 가이드](docs/brand/astergraph-final/GUIDELINES.md)와 [로고 키트](docs/brand/astergraph-final/astergraph-logo-kit.zip)를 제공합니다.

## 마지막 장면: 분석을 뒷받침하는 온톨로지

0–27초는 기존의 사용법·영향 분석·대응안 비교를 보여줍니다. 마지막 27–30초는 **“모든 판단의 기반, 관리되는 기업 온톨로지.”**라는 메시지와 함께 관계 모델·시스템 매핑·관리 버전 맥락을 보여줍니다. 노드를 선택하거나 `관계 모델 살펴보기`로 읽기 전용 Explorer를 열 수 있습니다. 이는 관리 구조의 목업이며 실제 백엔드 운영 상태를 뜻하지 않습니다. 권장 마무리 내레이션: “그 기반은, 관리되는 온톨로지.” (음성 파일은 포함하지 않습니다.)

### 기업 온톨로지 탐색

마지막 `6 결론`과 `Ontology Explorer`는 같은 읽기 전용 작업대를 제공합니다. 개념 또는 시스템 이름으로 검색하거나 원천 시스템을 선택하면 일치하는 노드가 강조됩니다. Enter로 첫 결과를 선택할 수 있습니다. 노드를 누르면 개념 설명과 연결 관계가, 관계명을 누르면 방향·업무 의미·연결된 개념이 표시됩니다. `데이터 예시`는 기존 분석 seed에서 가져온 목업 값이며 실시간 조회가 아닙니다. `모델 보기 초기화`는 검색·필터·선택을 복원합니다. 자동 재생 중 수동 탐색하면 재생이 정지합니다. 모바일에서는 개념 목록과 상세 관계 목록으로 탐색합니다.
