## 디자인 정체성 판단

고정된 운영 상황, 38=26+12의 결과 분해, 선택 주문의 재고 근거를 한 화면에 유지하는 구조는 AsterGraph에 적합한 전문 작업대다. 일반적인 대시보드보다 제품의 업무 목적이 분명하다. 완성도를 낮추던 부분은 새로운 장식이 아니라 관계를 해석하는 비용, 비교 장면의 반복 표현, 일부 상태 안내와 작은 화면의 정렬 문제였다. 기존 네이비·틸·코랄, 세 열 작업 구조와 안정적인 장면 전환을 유지했다.

독립 디자인 평가 A는 수정 전 구조를 평가했다. B는 A의 내용을 보지 않고 수정 후 CLI와 실제 브라우저를 검사했다. 따라서 아래 30/40은 **수정 전 기준 평가**이며, 수정 후 점수를 임의로 높이지 않는다. 최종 품질의 근거는 해결 내역과 실제 렌더링·회귀 검사다.

## 유지한 강점

- KPI를 독립 성과 카드가 아닌 하나의 결과 띠로 표현한다. 틸과 코랄의 의미가 일관된다.
- 목록에서 비교로 전환해도 상황·질문·선택 주문의 근거가 같은 위치에 남는다.
- 같은 척도의 38→12 비교와 재고 0인 LM-1027을 함께 제공해 완전 해결처럼 과장하지 않는다.

## 인지 부하와 시연 흐름

수정 전 인지 부하는 중간 수준이다. 시나리오와 근거를 유지해 기억 부담을 줄이는 점은 좋지만 비교 장면의 반복 숫자, 숨겨진 관계 의미, 일반 모드의 6개 장면 선택이 시선을 나눴다. 장면 선택은 녹화 도구로서 필요하며 Record Mode에서 사라지므로 제거하지 않았다.

감정 흐름은 운영 문제 인지 → 영향 수치 확인으로 안도 → 그래프 해석에서 잠시 지연 → 대응 비교에서 판단 확신으로 이어진다. 이번 수정은 그래프 해석 지연과 비교 장면의 경쟁 요소를 줄였다. 12건의 잔여 위험과 조건부 시뮬레이션 표현은 유지한다. 12~19초와 19~27초의 읽기 시간, 30초 전체 타임라인에는 변경이 없다.

## 사용자별 위험 신호와 대응

- **운영 담당자:** 왜 이 주문에 재고를 배정할 수 있는지 여러 노드를 클릭해야 했다. 업무 관계명을 노출하고 SKU·가용 수량·이 주문의 배정 수량을 유지했다.
- **처음 보는 파트너:** 축소된 영상에서 작은 조건과 반복 컨트롤이 핵심을 가렸다. 주요 보조 글자를 14px로 맞추고 비교·대응 행의 위계를 정리했다.
- **키보드 사용자:** 관계 사이의 공간에 외곽 초점 링이 침범할 수 있었다. 그래프 내부 링으로 조정했고 기존 키보드·Escape·포커스 복귀 검사를 통과했다. 전체 VoiceOver 탐색은 미검증이다.

## 기계 검사와 실제 검증

Impeccable CLI는 수정 후 한 번 검사하여 `[]`, 종료 코드 0을 반환했다. 발견 0건, 규칙 0개, 지적 파일/위치 0개이며 분류할 오탐도 없다. 이 결과를 디자인 품질의 증명으로 취급하지 않았다. 실제 화면에서 발견한 Data Sources 겹침은 별도로 수정했다.

- 타입 검사·프로덕션 빌드 통과, 단위 테스트 24개 및 브라우저 테스트 10개 통과.
- 수정 후 30초 자동 재생 3회, 각 회차의 결과·근거·비교·엔딩 확인. 앱 시계는 30,000ms에서 종료한다.
- 1920×1080, 1440×900, 맥북 크기 1710×1107/1710×924 자동 검사. 실제 Chrome 1710×923도 육안 확인.
- 38/26/12, 두 대표 주문, 적용·해제, 필터·페이지, 정지·재개·리셋·장면 이동, 녹화 모드와 reduced-motion 재검증.
- 원본 seed·순수 계산 함수·타임라인은 변경하지 않았다. 외부 네트워크 차단 재생에서 외부 HTTP 요청 0건. Chrome/IAB 오류·경고 0건.
