# 구현 검증 기록

검증일: 2026-11-01. 제품 기준: `ASTERGRAPH_VALUE_FIRST_SPEC.md` v2.0. 시각 기준: `DESIGN.md`.

## 확인한 사용자 흐름

사용자가 운영 질문을 선택·실행하면 로컬 주문·재고 분석 결과가 KPI와 목록에 표시된다. 주문을 선택하면 같은 결과 객체의 관계 근거를 보여주고, 계획 미리보기에서 대체 출고 대상과 잔여 위험을 비교한다. 서버 API 경계는 없으며 모든 계산은 브라우저 내부 순수 함수다.

## 환경

- macOS / Apple M5, Node.js 26.0.0, npm 11.12.1.
- React + TypeScript + Vite + Tailwind CSS, 버전은 `package-lock.json` 참조.
- 브라우저: 설치된 Google Chrome. Playwright의 Chrome 채널로 실제 DOM·스타일·상호작용을 검증.
- 맥북 내장 디스플레이: 물리 2880×1864 Retina. 현재 macOS 논리 해상도는 1710×1107, 실제 Chrome 콘텐츠 뷰포트는 1710×924로 측정.

## 검증 범위

| 경계 | 검증 방법 |
|---|---|
| 실행 | 개발 서버 HTTP 200, 실제 Chrome 렌더 |
| UI → 명령 | 추천 질문, 분석 실행, KPI·필터, 페이지 이동, 주문 선택 |
| 명령 → 데이터 | 순수 함수와 reducer 단위 테스트 |
| 결과 → UI | 38/26/12, 두 대표 주문의 가용 재고·배정 수량, 전후 막대 |
| 계획 → 원본 | freeze된 seed와 직렬화 전후 비교, 반복 분석 |
| 재생 → 복원 | 6개 경계와 내부 이벤트 단위 테스트, 비순차 장면 이동 |
| 시계 → 렌더 | 실제 30초 재생 3회, 각 회차의 영향·근거·계획·엔딩 확인 |
| 외부 네트워크 | 브라우저 테스트에서 127.0.0.1 외 요청 차단 및 요청 목록 확인 |
| 접근성 | 키보드 입력 보호, 대화상자 Escape·초점 복귀, reduced-motion, 색 외 텍스트 상태 |

레이아웃 테스트는 1920×1080, 1440×900, 1710×1107, 1710×924에서 6개 장면의 페이지 크기와 핵심 패널의 scroll/client 치수를 비교한다. 핵심 화면에 세로·가로 스크롤이나 패널 내용 초과가 없는지 검사하고, 영향·비교 장면 PNG를 저장한다. 390×844에서는 가로 넘침 없이 세로 스크롤로 기능을 사용하는지 검사한다.

## 수정한 문제

- 1440×900에서 질문 패널 하단의 대응안 버튼이 재생 제어와 겹침: 장애 요약 여백과 반복 안내를 줄임.
- 초기 상태 및 미지원 질문 안내가 패널 밖으로 밀림: 비활성 이유를 질문 안내로 통합하고 복구 버튼을 기존 추천 질문 위치에 배치.
- 선택 노드의 상세 관계가 근거 패널을 밀어냄: 설명 높이를 예약하고 작은 데스크톱에서 패널 간격을 조정.
- 분석 중 다른 화면으로 이동할 때 완료 이벤트가 취소되어 로딩이 남을 가능성: 유효한 분석 세대는 탐색 간 유지하고, 입력 변경·리셋·장면 이동만 무효화.
- 그래프 연결선: 계산 결과의 edge 목록에서 방향과 연결 위치를 파생하도록 구성.
- 초반 테스트의 미지원 입력 수정 이후 선택자와 실행 중 소스 변경으로 인한 HMR 영향을 수정·제거하고, 최종 소스에서 재검증.
- 개발 갱신 중 React 루트 중복 생성 경고: ErrorBoundary를 앱 진입점에서 별도 컴포넌트로 분리했다. App과 ErrorBoundary를 각각 변경·복원하여 HMR 실행 후 콘솔 오류와 중복 루트 경고가 없는 것을 확인했다.

## 결과

최종 소스 기준으로 다음을 통과했다.

- `npm test`: 단위 테스트 **24개 통과**.
- `npm run build`: TypeScript 검사와 Vite 프로덕션 빌드 통과. 별도 `npm run typecheck`도 통과.
- `npm run test:e2e`: 브라우저 테스트 **10개 통과**, 총 약 1.9분.
- 초기 구현 시 오류 경계 파일 분리 후 재생 계산에 영향이 없는 브라우저 테스트 **9개를 추가 재검증**했고 모두 통과했다. 분리 전후 프로덕션 JS 해시가 동일하므로 3회 재생 검증의 대상 코드는 같다.
- 30초 자동 재생을 실제 시간으로 **3회 연속 완료**. 각 회차의 테스트 관측 시간은 30,354ms / 30,322ms / 30,351ms. 이는 버튼 조작·검증 대기 오버헤드를 포함하며, 앱의 시계는 매회 30,000ms에서 종료됨을 별도로 확인했다.
- 1920×1080 / 1440×900 / 맥북 논리 1710×1107 / 실제 Chrome 콘텐츠 1710×924에서 6개 장면의 무스크롤·무잘림 검사 통과.
- 390×844에서 가로 넘침 없이 대상 목록 접근 가능.
- 외부 요청 차단 상태의 전체 재생에서 외부 HTTP 요청 **0건**.
- 최종 핵심 프레임을 직접 보고 수치·근거·비교의 가독성을 검수했다.

## 검증 한계

- 실제 화면 녹화 파일과 음성 내레이션은 생성하지 않았다. 브라우저 프레임과 실제 재생을 확인했으며 영상 촬영 절차는 README에 있다.
- Safari·Firefox 및 Windows의 별도 렌더링 검증은 수행하지 않았다.
- 스크린리더 전체 탐색, OS 화면 녹화 인코더, 최종 영상 편집 결과는 검증하지 않았다.
- 시계는 30,000ms에 종료되지만 브라우저 스케줄링과 화면 캡처에 따른 한 프레임 수준의 차이는 최종 녹화에서 조정해야 한다.
- 테스트가 확인하는 것은 가정된 로컬 시나리오의 일관성이다. 현실 물류의 납기·비용·예약·SLA 판단이나 실제 운영 성과를 검증한 것이 아니다.

## 디자인 리뷰 후 재검증

Impeccable 독립 비평 A와 렌더링·검사 B를 분리해 진행했다. 검사기는 수정이 끝난 뒤 `src/features src/app src/demo src/components` 범위를 한 번 검사했으며 종료 코드 0, 결과 `[]`(발견 0건)이었다. 네이티브 브라우저가 읽기 전용 evaluate만 제공하므로 오버레이 주입과 별도 overlay 서버는 사용하지 않았다. Chrome/IAB 스크린샷, DOM, CLI 검사를 대신 사용했다.

- 근거 관계의 업무 레이블, 비교 숫자의 기준선, 대응 행의 위계, 필터별 제목, 상태 안내, 내부 이동 아이콘을 수정했다. 그래프의 초점 링은 노드 내부로 옮겨 관계 레이블과 겹치지 않게 했다.
- Ontology의 Order→Shipment 선을 OrderItem 아래로 우회하고 실제 관계 방향과 선택 경로를 표시했다.
- 1440×900 Data Sources의 컨트롤 겹침을 실제 화면에서 발견해 수정했다. 보조 화면의 패널 넘침과 컨트롤 침범도 기존 회귀 테스트에 추가했다.
- 글자를 키운 후 비교 패널 높이 초과가 발생해 1440/1920의 간격을 각각 조정하고 재실행했다. 최종 소스에서는 타입 검사·빌드, 24개 단위 테스트, 10개 브라우저 테스트가 모두 통과했다.
- 수정이 끝난 최종 소스에서 실제 30초 재생 3회를 다시 검증했다. 이 문서 위의 회차 시간과 verification-results.json은 이번 최종 실행 결과로 갱신했다. 38/26/12, LM-1001/LM-1027, 적용·해제, 정지·재개·리셋·장면 이동, 녹화 모드와 reduced-motion을 포함한다.
- 네이티브 Chrome에서 1920×1080, 1440×900 및 이번 세션의 실제 맥북 콘텐츠 1710×923을 직접 확인했다. 자동 검증은 1710×1107/1710×924도 포함한다. Chrome과 독립 IAB의 오류·경고 로그는 0건이다.
- 핵심 화면과 보조 화면을 두 목표 해상도에서 캡처했다. 위의 핵심 스크린샷은 최신 화면으로 교체했다. [Data Sources 1440](screenshots/sources-1440.png), [Ontology Explorer 1440](screenshots/ontology-1440.png)도 보관했다.
- 검수용 탭·뷰포트 변경과 작업에서 시작한 개발 서버를 정리했다. 실행은 README의 `npm run dev`를 사용한다.

기존 검증 한계는 유지된다. 실제 운영 사용자 대상 이해도 테스트, Safari/Firefox 및 전체 VoiceOver 검수, 최종 인코딩 영상의 가독성 평가는 이번 작업에서 수행하지 않았다.

## 로고·라이트/다크 테마 추가 검증

2026-11-01 후속 작업. A와 연결 경로를 조합한 SVG 로고를 사이드바·모바일 헤더·엔딩·favicon에 적용하고, 기본 다크 및 선택 가능한 라이트 테마를 구현했다.

- `npm run typecheck`, `npm run build`, `npm test`: 통과. 단위 테스트 24개.
- `npm run test:e2e -- --grep-invert 'three full'`: 기존 상호작용·레이아웃과 신규 테마 검사 총 13개 통과, 26.7초. 90초 분량의 기존 3회 연속 재생 검사는 이번 표시 설정 변경에서는 재실행하지 않았다. 앞선 3회 검증 기록은 그대로 유지한다.
- 테마의 새로고침 유지, 키보드 전환, 분석·계획 유지, 녹화 중 버튼 숨김, 저장소 접근 차단 시 전환, 390px 모바일 헤더를 확인했다.
- 1440×900·1920×1080에서 라이트 모드 6개 장면과 모든 보조 화면을 검사했다. 다크 모드의 두 목표 해상도와 맥북 크기도 기존 레이아웃 테스트를 통과했다.
- 라이트 Raised 표면 위 Ink/Secondary/Muted/Blue/Teal/Coral 여섯 토큰의 대비를 실제 브라우저 스타일에서 계산해 모두 4.5:1 이상임을 확인했다.
- 최초 라이트 캡처가 300ms 전환 중 촬영되어 흐려진 것을 발견했다. 테스트 캡처에서 유한 애니메이션을 완료시키도록 수정하고 두 해상도의 캡처 검사를 재실행했다. 앱의 실제 모션은 변경하지 않았다.
- Chrome 직접 제어 연결을 사용할 수 없어 네이티브 IAB로 두 테마와 브랜드 엔딩을 육안 검수했다. 자동 회귀 검사는 설치된 Chrome 채널을 사용했다. Safari/Firefox 및 전체 스크린리더 탐색은 미검증이다.
- 기존에 실행 중이던 5173 개발 서버를 사용했다. 추가로 시작된 5174 서버만 종료했다.
